# 当日分析（自动盘中观察，不交易）

## 选择跟踪对象

读取正式推荐历史和已完成影子报告，要求recommendation_date是交易日、其下一交易日等于当天target_date、生成时间早于目标日零点。影子事后报告可作为观察来源，但标识来源，不用于前瞻收益统计。当天临时重新选出的票不冒充前日推荐。正式/影子同代码合并，最多两只；不同代码分别记录。当天首次执行前冻结名单，盘中修改推荐不会悄悄替换跟踪对象。

## 自动调度

独立IntradayScheduler随web服务启动，不依赖14:30日推荐调度是否启用。默认开启，管理员可在当日分析页面暂停/启用；不会关闭正式推荐定时任务。北京时间交易日09:30、09:40……11:30，以及13:00……15:00，每只股票每时段仅一次，共26个时点，午休/非交易日不执行。使用项目既有交易日历，未知年份不猜测。

后台20秒检查一次，服务必须保持运行。迟启动只处理当前10分钟窗口，不补造错过窗口的实时行情。关闭/重启后同一(day,slot,code)不重发模型请求，包括失败或中断时段；这是避免重复扣费的保守策略，不是服务商exactly-once保证。只有下一窗口会继续，页面标记超过180秒仍running的记录为中断。进程锁防止并发重复调度；新web服务已有独占端口保护。

## 行情与分析

复用腾讯get_quotes工具，验证代码、有效价格、数值、同日行情时间，允许最多120秒延迟及5秒时间偏差；过期报价标记quote_failed且不调用模型。采集跨窗口则不将新行情冒充旧时段。仅保留公开字段。历史使用当天该股票最近最多5个已采集快照，计算相对上次价格变化、累计成交额之差；累计成交额下降时不据此推断卖出，首条记录无伪造区间趋势。

每个有效时段使用系统当前启用模型（地址、密钥、代理配置沿用系统档案）发出一次原生submit_review工具调用，40秒超时，模型输出继续受2400输出Token限制。无任意URL、代码执行或下单工具。输出经schema/证据ID校验：摘要、观察事实、可能解释、替代解释、风险等级、继续观察条件与局限。不能凭行情断言主力身份或真实意图，不得编造L2、逐笔委托或资金净流入，也不假定用户持仓成本。

模型失败保留真实报价，标analysis_failed，不用规则文字假冒模型成功。上游返回usage就记录发送/响应Token，未报告则为null；任务是系统共享用量，不冒记到某个登录用户，管理员可在当日分析和Token统计页面查看该日用量。默认两只股票最多约52次模型请求/完整交易日；同票合并或报价失败则更少，真实费用按服务商用量收取。

## 留存与权限

数据在runtime/intraday/observations.db，配置runtime/intraday/config.json。保存名单、时段、采集时刻、原行情、派生指标、模型结论、引用、用量和失败原因。intraday_*、tool_*、shadow_llm_request/response日志进入服务控制台及runtime/logs/backend.jsonl。模型请求/响应是业务调试数据，分享日志前需检查。

菜单所有已登录角色可见，GET /api/intraday只读，date可查历史；普通用户/经理不返回用量。POST /api/intraday/config仅管理员，保留Host、Origin、CSRF和登录校验。页面“同步已保存结果”以及15秒页面轮询不调用行情/模型。

本地测试：test_intraday.py覆盖时段/休市/午休、去重、增量、过期行情拒绝、暂停/无票不调用、失败留存、名单冻结、前日与同代码归并；test_auth.py覆盖角色权限及CSRF。preview_intraday.py仅为隔离假数据UI验收，不导入生产。
