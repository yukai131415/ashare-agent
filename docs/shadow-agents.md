# 多 Agent 影子选股（实验，不替换正式系统）

## 当前版本：按需全市场检索

### 必经多维探索（2026-10-25更新）

数据准备先强制执行四路全快照检索：成交额降序、涨跌幅降序、换手率降序、正市盈率升序，每路取5只，合并按股票代码去重（最多20只，重复较多时会少于20只）。市盈率为零、负数和缺失不作为“低估值”候选；每维度记录扫描量、有效指标量、返回代码及排序方向。均为公开指标探索，不是私有策略评分，也不承诺低市盈率即低风险。

随后集中查询去重候选截止日前的财务，成功、无披露、接口失败和时间不足分开记录；采集总100秒预留不变，未查到不能冒充成功。逐股检查PE、换手率、量比和财务证据完整性，异常作为风险提示，未知不自动等同经营差或否决。基本面与风控直接依据这份证据提交，技术角色仍可按需查资金或研报。

exploration_coverage保存维度、候选、财务及完整性风险检查，写入报告、控制台和页面。决策提交必须满足四路探索完成且所选股票有财务成功记录，单次search_market前5名不能代替该覆盖。历史报告不自动重算；仅新运行应用必经准备。

2026-10-25起，新生成的完整市场快照不再按成交额截取12只，也不依赖私有推荐排序。冻结同日分析快照中符合市场准入、价格有效且行情时间不晚于截止时间的全部股票，仅保留公开字段。这里“全市场”指已采集且通过准入的快照，不承诺所有上市股票都有数据。

`search_market`支持公开指标排序、成交额/涨跌幅阈值、代码或名称检索以及offset分页；每页1至20只，固定代码排序打破并列，返回总体量/匹配数/是否还有下一页和snapshot证据ID。模型自行选择检索条件，再通过get_financials/search_research/historical_funds查询个股，禁止任意URL、SQL或代码执行。未知代码、未实际查阅的推荐、越界页大小和非有限阈值均拒绝。每轮最多展开60只快照是费用约束，不是按成交额预先锁定的候选池；工具仍可检索整个冻结范围。

全市场模式使用精简提示和前序研究摘要。按用户要求已取消累计30000 Token停止阈值，同时取消7000/14000/21000 Token阶段提前收敛；max_reported_tokens返回null表示无累计Token上限。仅请求次数或时间接近总预算时提前提交。Token用量和费用相关日志继续累计，单轮可能消耗更多额度；服务商自己的限额仍然有效。

不预取全市场财报、不将全市场行和代码枚举塞进提示词；仅提供市场规模、已查阅行情、前序研究和按需证据。每个非决策角色最多3次工具调用及一次纠正，总模型请求最多16次、300秒。累计输入字符仅统计，不再作为停止条件；单次请求（messages及工具schema）的序列化字符上限100000。达到其他预算仍可能中止，不保证查遍所有股票或选出全市场最优。

页面展示可检索数量和已查阅数量；最终只选已有证据的股票。管理员手动刷新将使用当前完整冻结范围并归档旧的12只样本报告；不自动改写历史。少量候选的旧报告继续兼容原模式，下文12只预取说明仅描述旧模式。未执行真实付费验证时不得将离线测试称为全市场模型实测。

正式 Supervisor 完成成功、未降级的流水线后，启动独立后台线程。影子链使用 LangGraph 编排基本面调查→技术研究→风险复核→影子决策。每个角色使用系统当前配置的同一模型，但有独立提示词、工具权限、会话及结构化结论；决策可与正式推荐不同，也可弃选，不是规则解释伪装成模型决策。

## 隔离和权限

- 正式推荐库、日锁、模型状态和历史回测不由影子链写入。结论单独写 `runtime/shadow/experiments.db`。
- 所有登录租户/角色可查看公共实验；只有管理员可手工启动或开关自动实验。Host、登录、权限和CSRF校验继续保留。
- 影子任务使用系统模型配置，不使用查看者私有租户的密钥。系统任务Token独立记账，只有管理员可在影子页和Token统计页查看累计，不归入某个登录用户，不受用户筛选影响。
- 配置 `config/settings.json.shadow.enabled=true` 开启功能；持久化运行开关在 `runtime/shadow/config.json`。关闭后停止新任务，不强制中断已经在请求中的实验。
- 同时最多一个影子任务，文件锁跨进程排除；同一天完成/弃选后锁定，失败最多两次尝试。中断留下running时可在确认原进程结束后手工重试。

## 输入和真实工具循环

输入是与正式推荐同日、通过原准入规则的候选快照，按成交额取最多12只后按代码排序，不代表全市场，也不是全量模型候选研究。只导出公开行情字段，不导出原评分、权重、模型名和标准化因子。正式推荐仅保存在对照字段，不放入模型输入，不强制模型跟随。

模型通过原生 Function Calling 返回工具名/参数，程序执行工具，将结果作为 tool/function_call_output 消息交回模型，最后必须调用 `submit_review`。调查角色最多追加1次工具查询，正常最多2轮模型调用；工具参数JSON解析失败时最多追加一次要求短文本完整JSON的修正，单角色最多3轮，总计仍最多8轮，修正请求也计入Token/时间预算，不拼接残缺JSON、不执行残缺参数。工具名、候选代码、输出结构、证据ID和风控否决均由后端验证。没有原生工具调用支持或失败时标记失败，不降级为规则选择。支持OpenAI兼容Chat Completions和OpenAI官方Responses，不支持的原生接口明确拒绝。

报告的stages记录数据准备、基本面、技术面、风控和决策的真实状态与开始/结束时间；console打印shadow_stage_changed。页面每2秒GET同步状态，执行中脉冲、完成变绿、失败变红，未执行阶段不伪装完成。读取状态不触发新模型请求。

submit_review按角色生成schema：前三角色selected_code枚举仅允许空字符串，决策角色允许空字符串或池内代码；候选与否决数组也限定池内代码。格式或语义校验失败共享同一次修正机会，返回tool错误要求模型重新提交，不静默删除模型字段；风险否决和证据引用校验仍然有效。多次不合规保留失败，不伪造结论。

基本面和风控可查财务/检索研报；技术可查历史资金（通过Stock Data MCP）/研报；决策只读取前置研究。财务截止到推荐日前一自然日，避免公告只有日期无法确认盘中可见性；研报按冻结推荐生成时间过滤；资金仅取推荐日前历史记录。没有实时行情、网络任意URL、Shell或交易工具。历史查询仍无法完全消除模型自身知识和供应商修订的后见偏差。

原生调用协议参考：https://developers.openai.com/api/docs/guides/function-calling

## 预算与失败

管理员影子页面提供系统模型档案下拉框。点击“刷新状态”POST `/api/shadow/refresh`，携带服务端已存在的profile_id，独立选择该档案的地址、密钥或环境变量、代理，不修改全局/租户问答配置。模型列表不返回密钥，不接收客户端任意接口或密钥。每次手动重研沿用原冻结候选/截止日、完整归档旧报告、累计原用量，强制不计前瞻统计；60秒冷却、单任务互斥及原8轮/300秒预算仍有效。此前“当日锁定”仅继续约束自动任务，用户明确点击的手动任务可以重新研究；普通用户和经理不能触发系统共享模型费用。页面定时GET只读状态，不自动重算。余额不足等失败会显示原因，不伪造推荐。

官方模型调用需要可达网络。2026-10-24本机直连超时，经Windows已配置的 `http://127.0.0.1:1100` 代理可达；系统模型配置显式使用该代理。网络失败显示代理/网络提示，HTTP鉴权等错误展示脱敏后的状态与原因，Responses未完成不误报为弃选。旧第二次修复若是无模型响应的URLError，仅允许额外一次网络恢复验证，不允许重抽已完成结论。API Key仍来自API_KEY环境变量，HTTP401时必须更新有效密钥，不重试绕过鉴权。

研究开始前按冻结候选池预取财务，采集阶段最多100秒，仍计入300秒总预算；失败/未查询保持未知。每只仅向模型提供最近一期公开指标（含数据源给出的营收/利润同比），使用简短字段名，保留报告期、披露日、来源及证据ID，不截断JSON；完整财报原始响应仍归档。全池财务已齐备时基本面和风控直接提交研究，避免重复查证；技术面保留一次追加查询。四个角色共享证据包，不可凭未提供的历史或现金流做推断；真实风险仍允许弃选。

管理员“补齐证据后重新研究”仅针对曾有财务查询失败的已弃选记录，允许一次有效重研；修复执行失败时仅额外重试一次，已完成或再次弃选不能继续刷结果。重新调用模型并产生Token费用，冻结股票池和时间截止不变；原完整报告先归档至 `runtime/shadow/archive/日期-before-evidence-repair.json`。修复结果强制标为事后，不计前瞻收益，前次用量保留，绝不修改正式推荐。连接复核本身不会触发此重跑。

财务工具采用最多三次有界尝试（两次原传输、一次同地址curl备用），401/403/429直接分类失败，不切换传输绕过。成功结果仅按相同股票＋相同截止日缓存30分钟，保留响应中的采集时间，不以文件修改时间充当新鲜度。失败细分timeout/tls/connection/access_denied/rate_limited等，诊断存于 `runtime/agents/fundamental/errors/`。模型工具错误会明确single_stock范围，禁止将一次失败扩写成全池没有财报。

管理员可点击“复核财务连接”，只重查最近实验中失败的至多两只股票，不调用大模型、不重跑选股。追加结果写 `runtime/shadow/financial_recheck.json`，不篡改锁定的原实验报告。页面展示真实财务查询覆盖数和未查询数；原模型文字不等于实际接口覆盖事实。

总时间300秒（外部请求取消清理可能略超），单模型请求至多40秒，单次最多2400输出Token。不按累计Token量或累计输入字符中止；单次输入超过100000字符在发出请求之前拒绝，此拒绝不计为模型调用。累计输入继续用于追踪重复上下文开销，不等同单次上下文窗口。提示要求summary不超过450字、风险不超过4条，避免冗长输出挤占JSON尾部。服务商不报告用量时显示未报告次数，不把它推定为0实际消耗。所有模型请求、结构化响应和角色事件打印控制台（密钥脱敏）。

## 前瞻与回测

只有在推荐当日15:00前完成的影子结果可进入前瞻样本；收盘后/周末补跑一律标事后实验，禁止计入前瞻统计。不自动批量补造历史影子选择。

目标交易日15:10后，后台按正式与影子两只股票的真实日线核算：`(目标日最高价 / 推荐日收盘价 - 1) × 100% - 1个百分点`，额外费用默认0。日线缺失、采集时间未确认收盘、一字价等保持待核验。结果保存在实验记录的outcome字段，不改正式回测。

前瞻统计只匹配两边均有有效日线的实验日，按逐笔复利计算，弃选、失败和事后实验不按0计入；因此不是完整账户净值。最高价减1个百分点是事后模拟，并不代表实际可成交。

## 验证

`PYTHONPATH=src python tools/verify_shadow.py`：最多启动一次最近日期的真实实验，核对正式推荐文件、推荐数据库、模型状态和health的SHA256是否保持不变；结果写入 `docs/verification/shadow_smoke.json`。测试模型用于单元测试的输出不写入真实实验库。
